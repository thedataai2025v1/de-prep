## 1. Problem Statement

Given an integer array `nums`, return all unique triplets `[nums[i], nums[j], nums[k]]` such that `i != j`, `i != k`, `j != k`, and `nums[i] + nums[j] + nums[k] == 0`. No duplicate triplets allowed.

**Example:**
```
Input:  nums = [-1, 0, 1, 2, -1, -4]
Output: [[-1, -1, 2], [-1, 0, 1]]
```

---

## 2. Approaches

### Approach 1: Sorting + Two Pointers (⭐ Optimal)

Sort the array first. For each element `nums[i]`, use two pointers (`left = i + 1`, `right = n - 1`) to find pairs that sum to `-nums[i]`. Skip duplicates to ensure unique triplets.

**Pros:**
- O(n²) time — optimal for the 3-sum problem
- Sorting makes duplicate skipping trivial
- Two-pointer technique is intuitive and easy to validate
- Scales to k-sum by nesting more pointers

**Cons:**
- O(n log n) overhead from sorting
- Must carefully skip duplicates at three different levels (i, left, right)
- Returns indices of values, not original positions (due to sorting)
- Not suitable if the array cannot be modified

```python
def threeSum(nums: list[int]) -> list[list[int]]:
    nums.sort()
    result = []
    n = len(nums)

    for i in range(n - 2):
        # Skip duplicates for i
        if i > 0 and nums[i] == nums[i - 1]:
            continue

        left, right = i + 1, n - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                result.append([nums[i], nums[left], nums[right]])
                # Skip duplicates for left and right
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1
                left += 1
                right -= 1

    return result
```

| Metric | Value |
|---|---|
| **Time** | O(n²) |
| **Space** | O(1) extra (or O(n) for sorting) |

### Approach 2: Hash Map with Two-Sum Inner Loop (Alternative)

For each element `nums[i]`, treat the remaining array as a two-sum problem using a hash map to find pairs that sum to `-nums[i]`. Use a set of sorted tuples to deduplicate.

**Pros:**
- Avoids sorting — preserves original indices
- Hash map approach is familiar from Two Sum
- Good for explaining the generalization from Two Sum to k-sum

**Cons:**
- O(n²) time on average but slower constants due to hashing
- O(n) extra space for the hash map per iteration
- Deduplication with tuples is messy and error-prone
- Harder to skip duplicates than with sorting

```python
def threeSum(nums: list[int]) -> list[list[int]]:
    result = set()
    n = len(nums)

    for i in range(n):
        seen = {}
        target = -nums[i]
        for j in range(i + 1, n):
            complement = target - nums[j]
            if complement in seen:
                triplet = tuple(sorted([nums[i], nums[j], complement]))
                result.add(triplet)
            seen[nums[j]] = j

    return [list(t) for t in result]
```

| Metric | Value |
|---|---|
| **Time** | O(n²) |
| **Space** | O(n) |

### Complexity Comparison

| Approach | Time | Space | Best For |
|---|---|---|---|
| **1. Sorting + Two Pointers** | O(n²) | O(1) extra | Interviews, optimal clarity and performance |
| **2. Hash Map with Two-Sum** | O(n²) | O(n) | When sorting is not allowed or indices matter |

## 3. Edge Cases

| Edge Case | Behavior |
|---|---|
| All zeros (`[0, 0, 0]`) | Returns `[[0, 0, 0]]` — single valid triplet |
| No zero-sum triplet | Returns `[]` |
| Duplicate values throughout | Skipping logic ensures no duplicate triplets |
| Less than 3 elements | Returns `[]` |
| Large negative numbers | Handled normally — two-pointer skips based on sum sign |

## 5. Interview Follow-Up Questions

**Q1: What if we don't allow sorting?**
-> Use the hash map approach. It avoids sorting but at the cost of O(n) extra space and messier deduplication. It also doesn't scale as well to k-sum generalizations.

**Q2: Can this be generalized to k-sum?**
-> Yes. Sort the array, then recursively fix elements and reduce k. For k = 3, it's O(n²). For k = 4, O(n³). Base case k = 2 uses the two-pointer approach on the remaining subarray. This is called the k-sum reduction.

**Q3: What if the array is very large (doesn't fit in memory)?**
-> Sort externally (disk-based merge sort), then stream the sorted data through the two-pointer algorithm in chunks. The same approach works for distributed data with merge joins in Spark or Hadoop.

**Q4: How do you ensure uniqueness of triplets without sorting?**
-> Use a set of sorted tuples (hash the sorted triple). This guarantees uniqueness but adds overhead. It's the standard way to handle deduplication without sorting the original array.

## 6. Common Mistakes

| Mistake | Why It's Wrong | Fix |
|---|---|---|
| Not skipping duplicates in the outer loop | Returns duplicate triplets like `[-1, -1, 2]` twice | `if i > 0 and nums[i] == nums[i - 1]: continue` |
| Moving both `left` and `right` after finding a match | May skip valid pairs | Move left and right (shrink window) after found |
| Not moving `left`/`right` after skipping duplicates (infinite loop) | `while left < right` never terminates | Left = left + 1, right = right - 1 after skip loops |
| Returning indices instead of values | Problem asks for values | Append `[nums[i], nums[left], nums[right]]` |
