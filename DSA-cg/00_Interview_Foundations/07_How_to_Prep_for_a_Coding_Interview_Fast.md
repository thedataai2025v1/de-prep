# How to Prep for a Coding Interview Fast

**Type:** Fast-track lesson  
**Goal:** Build the highest-value preparation loop when time is limited.

## 1. Prioritize patterns, not random problem volume

A practical order:
1. Arrays, hash maps and sets.
2. Two pointers and sliding windows.
3. Prefix sums.
4. Binary search and sorting.
5. Stacks, queues and monotonic stacks.
6. Linked lists.
7. Trees and tries.
8. Heaps and intervals.
9. Graph BFS / DFS / topological sort.
10. Backtracking and dynamic programming.

This is a learning sequence, not a guarantee of interview frequency.

## 2. Minimum viable daily session (120 minutes)

| Time | Activity |
|---:|---|
| 10 min | Recall one pattern from memory |
| 20 min | Study one worked example |
| 40 min | Solve one unseen problem |
| 20 min | Test, dry-run and analyze |
| 20 min | Explain aloud and record mistakes |
| 10 min | Re-solve a previously missed step |

## 3. Use a three-pass method

- **Pass 1 — Learn:** Read the explanation and implement with guidance.
- **Pass 2 — Recall:** Re-solve without notes the next day.
- **Pass 3 — Transfer:** Solve a different problem using the same pattern.

A problem is not mastered merely because its solution looked familiar.

## 4. Readiness scorecard

Rate each pattern from 0 to 3:
- 0: Cannot identify the pattern.
- 1: Can explain after seeing the solution.
- 2: Can solve a familiar variant independently.
- 3: Can solve an unseen variant and defend trade-offs.

Prioritize patterns scored 0 or 1.

## 5. Principal Data Engineer adaptation

Reserve time for practical Python:
- Parse nested JSON safely.
- Deduplicate events deterministically.
- Merge sorted streams.
- Aggregate records in bounded memory.
- Implement an LRU cache or rate limiter.
- Handle malformed records and retries.

## 6. Common failure modes

- Solving many problems while never revisiting mistakes.
- Memorizing code instead of understanding invariants.
- Skipping complexity and edge-case discussion.
- Practicing only easy variants.
- Neglecting communication under time pressure.

## Final checklist

At the end of a session, record: pattern, problem, first failed attempt, corrected invariant, complexity, edge case missed, and date for reattempt.
