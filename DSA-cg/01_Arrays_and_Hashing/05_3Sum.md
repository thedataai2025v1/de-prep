## 1. Problem Statement

Return all unique triplets of distinct indices whose values sum to zero. Do not return duplicate value triplets.

**Example:**
```text
nums = [-1,0,1,2,-1,-4]
Output = [[-1,-1,2],[-1,0,1]]
```

**What I would clarify before coding:**
- Are inputs empty or null, and what should be returned?
- May I modify the input?
- Are duplicates, negative values or ties possible?
- Does output order matter?

## 2. Approaches

### Approach 1: Baseline / Brute Force

**Idea:** Enumerate all triples, test their sum, sort each valid triple and deduplicate with a set.

```python
def three_sum(nums):
    found = set()
    n = len(nums)
    for i in range(n):
        for j in range(i + 1, n):
            for k in range(j + 1, n):
                if nums[i] + nums[j] + nums[k] == 0:
                    found.add(tuple(sorted((nums[i], nums[j], nums[k]))))
    return [list(x) for x in found]
```

- **Complexity:** O(n³) time; output/set space

**Pros:**
- Directly mirrors the problem statement and is a useful correctness baseline.
- Usually easy to explain and validate with small examples.

**Cons:**
- Often performs repeated work and may not scale to the maximum constraints.

### Approach 2: Optimized Approach

**Idea:** Sort once, fix one value, then use two pointers for the remaining pair; skip duplicate values.

```python
def three_sum(nums):
    nums.sort()
    out = []
    for i in range(len(nums) - 2):
        if i and nums[i] == nums[i - 1]:
            continue
        if nums[i] > 0:
            break
        left, right = i + 1, len(nums) - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                out.append([nums[i], nums[left], nums[right]])
                left += 1; right -= 1
                while left < right and nums[left] == nums[left - 1]:
                    left += 1
                while left < right and nums[right] == nums[right + 1]:
                    right -= 1
    return out
```

- **Complexity:** O(n²) time after sorting; output space excluded

**Pros:**
- Uses the problem's structure to reduce unnecessary work.
- Suitable for the expected interview constraints.

**Cons / trade-offs:**
- Requires a clear invariant or data-structure choice.
- Additional memory or input mutation may be involved; state the contract explicitly.

### Which approach should I choose?

**Recommended:** Sort once, fix one value, then use two pointers for the remaining pair; skip duplicate values.

Choose the optimized approach after explaining the baseline and proving why the optimization is correct. If the interviewer values simplicity over asymptotic improvement for tiny inputs, explain that trade-off.

## 3. Step-by-Step Dry Run

Sort to [-4,-1,-1,0,1,2]. Fix -1: pair (-1,2) gives zero; then (0,1) gives zero. Skip the second fixed -1 to avoid duplicate triplets.

## 4. Interview Conversation

**Interviewer:** How do you prevent duplicate triplets?

**Candidate:** Sort, skip repeated fixed values, and skip repeated left/right values after recording a valid triplet.

**Interviewer:** Why move left when the sum is too small?

**Candidate:** The sorted order means increasing the left value is the only way to increase the sum with right fixed.

**Interviewer:** Why can you stop when nums[i] is positive?

**Candidate:** All remaining values are at least as large, so no triplet can sum to zero.
